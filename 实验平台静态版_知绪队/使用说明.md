# 生成式AI对话实验平台 — 静态版使用说明

这是「知绪队」实验平台的**纯静态版本**：不需要自建服务器、不需要装 Node，
把整个文件夹丢到任意静态托管（GitHub Pages / 腾讯云 COS / 阿里云 OSS / Netlify / Vercel）
或直接用浏览器打开 `index.html` 即可施测。

---

## 一、文件结构

```
static-site/
├─ index.html              页面主体（知情同意 → T1 → 对话 → T2 → 完成）
├─ assets/
│  ├─ config.js            【所有配置都在这里】：轮次、系统指令、量表、模型参数
│  ├─ app.js               前端逻辑（分组、对话、计分、生成结果码）
│  └─ style.css            样式
└─ tools/
   ├─ build.js             从 experiment-platform/config/*.json 重新生成 assets/config.js
   ├─ decode.js            把被试粘贴回来的结果码批量解码为 results.csv
   └─ proxy-worker.js      Cloudflare Worker 中转（解决 CORS + 隐藏 API Key）
```

## 二、三种运行模式

| 模式 | 配置 | 适用场景 |
|---|---|---|
| **测试模式（默认）** | `llm.mock = true` | 走查流程、试测、答辩演示。AI 回复是固定样例文本，页面顶部会显示黄色提示条。 |
| **浏览器直连** | `llm.mock = false` + 填 `api_key` | **不推荐**。多数大模型接口不允许浏览器跨域（CORS 被拦截），且 API Key 会明文暴露在页面中，任何人 F12 都能拿走。 |
| **中转代理（推荐）** | 填 `proxyUrl` | 正式施测。详见第四节。 |

## 三、正式施测前必做的 4 步

1. **部署 `tools/proxy-worker.js`**
   - 注册 Cloudflare 账号 → Workers & Pages → 创建 Worker → 粘贴代码 → 部署
   - 在 Settings → Variables 里配置三个环境变量：
     - `LLM_BASE_URL`：如 `https://api.deepseek.com/v1`
     - `LLM_MODEL`：如 `deepseek-chat`
     - `LLM_KEY`：你的 API Key
   - 复制 Worker 的网址（如 `https://zhixu-llm.xxx.workers.dev`）

2. **编辑 `assets/config.js`**
   ```js
   "llm": { "mock": false, "temperature": 0.7, "max_tokens": 500 },
   "proxyUrl": "https://zhixu-llm.xxx.workers.dev",
   ```
   - `api_key` 保持留空（密钥只放在 Worker 里）
   - `temperature` 建议固定为 0.7，两次施测之间不要再改，保证条件一致性

3. **上传整个文件夹**到静态托管，拿到公开网址（如 `https://xxx.pages.dev`）。

4. **把网址填进 Credamo 问卷**的「跳转链接」或嵌为「网页素材」，
   并在问卷最后加一道**填空题**让被试粘贴结果码。

## 四、数据怎么回收（重点）

静态页没有后端，数据不会自动进数据库。回收链路是：

> 被试完成 → 页面生成一段**结果码**（base64）→ 被试复制并粘贴回问卷填空题
> → 你导出问卷 → 把结果码列成一列存成 `codes.txt` → `node decode.js -f codes.txt` → `results.csv`

页面上同时提供「下载完整记录（含对话原文）」按钮，如果愿意，也可以让被试把 json 文件
作为附件上传（但会增加被试负担，一般不建议）。

**批量解码：**
```bash
node tools/decode.js -f codes.txt
# → 输出 results.csv，并打印分组人数（高EI / 低EI）与同伴支持分层分布
```

## 五、和动态版（`experiment-platform/`）的区别

| 项目 | 动态版 | 静态版 |
|---|---|---|
| 部署 | 需 Node 服务器 | 任意静态托管 |
| 随机分组 | **分层区组随机**（同伴支持 L/M/H 各层内 2:2 配平） | **简单随机**（各 50%） |
| 数据落库 | 自动写入 `data/*.jsonl`，可导出 CSV | 靠结果码回收 |
| 组间平衡 | 有保证 | 无保证 |

> **对研究二的影响**：研究二要用 PROCESS Model 7 检验"同伴支持 × EI 条件"的交互，
> 需要每个同伴支持水平层内都有足够的高/低 EI 被试。静态版的简单随机在样本量大时
> （比如 300 人）实际偏差很小，但**如果正式施测，强烈建议用动态版**，
> 它的分层区组随机能保证各层严格配平。静态版更像"备用方案 / 演示版"。

## 六、常见问题

- **页面提示"回复获取失败：HTTP 0 / CORS"** → 没有配 `proxyUrl`，见第三节。
- **改了量表题目** → 改 `assets/config.js` 的 `scales`，或直接改
  `experiment-platform/config/scales.json` 后执行 `node tools/build.js` 重新生成。
- **想改最短对话轮数** → `assets/config.js` 的 `minTurns`（默认 7，对应方案中"≥7 轮"）。
- **危机话术触发** → 被试输入命中 `crisisKeywords` 时，系统指令会强制 AI 使用统一危机话术，
  同时计入 `crisis` 字段，事后需人工核查这些个案。

## 七、伦理与合规提醒

- 知情同意、随时退出、事后解释（debrief）已在页面内实现，不要删改。
- 结束页的心理支持资源（12356 / 400-161-9995）请按本校实际情况核对后保留。
- 若 `crisis` 字段 > 0 的个案，需按伦理预案进行随访。
